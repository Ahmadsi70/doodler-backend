# Detailed Technical Analysis: Image Generation Pipeline (SDXL-Turbo, Prompt Engineering & Texture Padding)

## 1. Executive Summary

This report provides a comprehensive technical investigation of the character image generation pipeline in the Doodler AI backend (`c:\Users\badri\Story`). The primary goal of this milestone (M0 / R1) is to enhance character generation by introducing **strict prompt templates** and **automatic image padding/resizing** when generating `texture.png`. This ensures that characters generated by SDXL-Turbo are full-body, isolated, symmetrical, and surrounded by a clean margin of white pixels along all 4 edges, preventing cut-offs, body part bleed, or aspect ratio distortion during AnimatedDrawings processing.

## 4. Prompt Engineering & Strict Prompt Template Analysis

### 4.1 Current Prompt Construction (Observed Code)
In `runpod_backend/server.py` (lines 132-135) and `handler.py` (lines 62-65):
```python
character_prompt = "A character design on a solid white background. "
parts = spec.get("sketch", {}).get("parts", [])
for p in parts:
    character_prompt += p.get("prompt", "") + ", "
```

#### Deficiencies of Current Approach:
1. **No Framing or Pose Control**: The prefix `"A character design on a solid white background. "` lacks explicit instructions regarding character pose (standing, front view, A-pose/T-pose) or framing (full body, whole body). As a result, SDXL-Turbo frequently generates cropped torsos, headshots, or dynamic perspective angles where feet or arms extend beyond image bounds.
2. **Weak Background Isolation**: Simple text prefixing does not reliably prevent shadows, floor textures, or environmental gradients.
3. **Unstructured String Formatting**: Naive string concatenation leaves trailing commas and lacks negative prompt cues or standard quality modifiers.

### 4.2 Proposed Strict Prompt Template Design

To ensure SDXL-Turbo produces clean, full-body, symmetrical character sheets suitable for AnimatedDrawings skeleton rigging, prompt construction must be refactored into a structured function:

```python
def build_strict_character_prompt(parts: list) -> str:
    """
    Constructs a strict, standardized prompt for SDXL-Turbo character generation.
    Forces full-body, isolated, front-facing, symmetrical character sheet styling.
    """
    # High-priority framing & isolation tokens
    prefix = (
        "full body character sheet, single isolated character, standing pose, "
        "symmetrical front view, A-pose, solid pure white background, "
        "clean vector line art style, simple doodle illustration, complete character"
    )
    
    # Part descriptions extracted from spec
    part_prompts = [p.get("prompt", "").strip() for p in parts if p.get("prompt")]
    parts_str = ", ".join(part_prompts) if part_prompts else "cute character"
    
    # Negative/Quality safeguard directives appended to prompt
    suffix = (
        "full body visible, head to toe, centered in frame, pure white background, "
        "no crop, no cut off limbs, no shadows, no frame border"
    )
    
    return f"{prefix}, {parts_str}, {suffix}"
```

## 5. Texture Saving, Resizing & Image Padding Analysis

### 5.1 Current Texture Processing (Observed Code)
In `runpod_backend/server.py` (lines 154-166):
```python
ad_char_dir = "/workspace/AnimatedDrawings/examples/characters/char1"

    im = Image.open(char_image_path).resize((w, h))
    im.save(os.path.join(ad_char_dir, "texture.png"))
```

#### Deficiencies of Current Texture Processing:
1. **Aspect Ratio Distortion**: Line 165 performs `im.resize((w, h))` directly on the 512x512 square image, stretching it vertically to fit 454x602 (~32.6% vertical distortion).
2. **Character Cut-Off / Zero Margin**: If the generated character touches or extends near the outer boundaries of the 512x512 frame, naive resizing keeps the character touching the canvas edge. AnimatedDrawings contour detection requires a pure white margin surrounding all 4 sides of the character.

### 5.2 Proposed Bounding-Box Padding & Resizing Algorithm

Using the RGBA output from `rembg` (`img_no_bg`), we can extract the exact bounding box of the non-transparent character pixels (`alpha > 0`), scale it to fit within target dimensions minus a specified padding margin, and paste it centered onto a pure white RGB canvas.

#### Proposed Algorithm Implementation:
```python
def process_character_texture(img_no_bg: Image.Image, target_w: int = 454, target_h: int = 602, margin_px: int = 30) -> Image.Image:
    """
    Pads and resizes transparent character image into target canvas with guaranteed white margins on all 4 edges.
    Preserves aspect ratio and centers the character.
    """
    # 1. Get bounding box of non-transparent pixels (alpha channel)
    alpha = img_no_bg.split()[3]
    bbox = alpha.getbbox() # Returns (left, upper, right, lower) or None
    
    if not bbox:
        # Fallback if image is entirely transparent
        return Image.new("RGB", (target_w, target_h), (255, 255, 255))
    
    # 2. Crop character to tight bounding box
    cropped_char = img_no_bg.crop(bbox)
    char_w, char_h = cropped_char.size
    
    # 3. Calculate max allowable character area inside target canvas considering margins
    max_w = max(1, target_w - (margin_px * 2))
    max_h = max(1, target_h - (margin_px * 2))
    
    # 4. Compute uniform scale factor preserving aspect ratio
    scale = min(max_w / char_w, max_h / char_h)
    new_w = max(1, int(char_w * scale))
    new_h = max(1, int(char_h * scale))
    
    # 5. Resize character with high-quality resampling (LANCZOS)
    resized_char = cropped_char.resize((new_w, new_h), Image.Resampling.LANCZOS)
    
    # 6. Create solid white target canvas
    canvas = Image.new("RGB", (target_w, target_h), (255, 255, 255))
    
    # 7. Calculate center offsets
    offset_x = (target_w - new_w) // 2
    offset_y = (target_h - new_h) // 2
    
    # 8. Paste resized character onto white canvas using alpha mask
    canvas.paste(resized_char, (offset_x, offset_y), mask=resized_char.split()[3])
    
    return canvas
```
